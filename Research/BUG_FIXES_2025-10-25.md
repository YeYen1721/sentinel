# Bug Fixes - October 25, 2025

## 🐛 Issues Resolved

### 1. ✅ Loading Spinner Stuck After Action Plan Generation

**Problem:**
- After Gemini successfully generated tasks, the loading spinner never disappeared
- Console showed Firestore permission errors, then hung indefinitely
- `isLoading = false` never executed

**Root Cause:**
- The `withTimeout` helper function used `TaskGroup` for timeout handling
- Firebase SDK doesn't respect task cancellation
- When Firestore operations failed (demo mode), they kept retrying forever
- The timeout never fired because Firebase SDK continued retrying
- This blocked the main thread, preventing `isLoading = false` from executing

**Solution:**
- Removed blocking `withTimeout` wrapper
- Replaced with fire-and-forget `Task.detached` pattern
- Firestore save now happens in background without blocking UI
- Loading spinner ends immediately after Gemini completes
- Tasks are still saved if Firestore is available, but it's non-critical

**Code Changes:**
```swift
// ❌ OLD (blocking):
do {
    try await withTimeout(seconds: 2) {
        try await taskRepository.createTasks(analysis.tasks, userId: userId)
    }
} catch {
    print("⚠️ Could not save to Firestore")
}
isLoading = false  // ❌ Never reached

// ✅ NEW (non-blocking):
Task.detached(priority: .background) {
    do {
        try await self.taskRepository.createTasks(analysis.tasks, userId: userId)
        print("✅ Tasks saved to Firestore")
    } catch {
        print("⚠️ Firestore save failed (non-critical): \(error)")
    }
}
isLoading = false  // ✅ Executes immediately
```

**Files Modified:**
- `/Sentinel/Core/ViewModels/DashboardViewModel.swift`
  - Removed `withTimeout` helper function (lines 11-26)
  - Updated `generateActionPlan()` to use fire-and-forget pattern (lines 186-193, 207-214)

### 2. ✅ Firebase Authentication Error at Startup

**Problem:**
- Firebase initialized with demo credentials
- Authentication failed, then fell back to demo mode
- Console showed authentication errors even though demo mode should be used

**Root Cause:**
- `GoogleService-Info.plist` contained demo credentials:
  - `API_KEY`: `YOUR_FIREBASE_API_KEY`
  - `PROJECT_ID`: `sentinel-demo-app`
  - These are invalid for Firebase authentication
- Detection logic only checked if `GOOGLE_APP_ID` contained `"YOUR_"` or `"DEMO"`
- The demo `GOOGLE_APP_ID` was `1:123456789012:ios:abcdef...` which doesn't contain those strings
- Firebase initialized with invalid credentials, causing auth to fail

**Solution:**
- Enhanced demo credential detection
- Now checks `API_KEY`, `PROJECT_ID`, and `GOOGLE_APP_ID` for demo/template markers
- If demo credentials detected, Firebase is NOT initialized
- App runs in pure demo mode without authentication errors
- Added helpful console messages for setting up real Firebase

**Code Changes:**
```swift
// ❌ OLD:
if let googleAppId = plist["GOOGLE_APP_ID"] as? String,
   !googleAppId.contains("YOUR_") && !googleAppId.contains("DEMO") {
    FirebaseApp.configure()  // ❌ Initialized with demo credentials
}

// ✅ NEW:
if let googleAppId = plist["GOOGLE_APP_ID"] as? String,
   let apiKey = plist["API_KEY"] as? String,
   let projectId = plist["PROJECT_ID"] as? String {

    let isDemoConfig = googleAppId.contains("YOUR_") ||
                       googleAppId.contains("DEMO") ||
                       apiKey.contains("DEMO") ||
                       apiKey.contains("YOUR_") ||
                       projectId.contains("demo") ||
                       projectId.contains("template")

    if !isDemoConfig {
        FirebaseApp.configure()  // ✅ Only for valid credentials
    } else {
        print("⚠️ Running in DEMO mode - Firebase not configured")
        print("ℹ️ Detected demo/template credentials")
    }
}
```

**Files Modified:**
- `/Sentinel/SentinelApp.swift`
  - Enhanced demo credential detection (lines 37-47)
  - Added better console messaging (lines 60-67)
